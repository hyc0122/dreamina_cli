# Native Launcher, Inline Asset Tools, and CLI Account Isolation Design

## 背景

本轮确认三个方向：

1. 启动管理器要做成程序 EXE 版本，不再把启动管理器作为网页页面交给用户。
2. 分镜工作台点击添加角色、场景、道具时，要把资产生图设置、批量生图、新建资产、批量删除、批量上传图片/音色、导入资产描述集成到同一个资产选择界面；导出仍保留在资产管理页。
3. 即梦 CLI 多账号当前不可靠。实测在全新空 `HOME / USERPROFILE / APPDATA / LOCALAPPDATA / XDG_* / DREAMINA_CLI_HOME` 下执行 `dreamina user_credit`，仍返回同一个已登录账号，说明官方 CLI 在 Windows 下还读取了固定登录态或系统凭据。不能继续把多个账号显示成“已隔离成功”。

## 推荐方案

### 1. 原生启动管理器

保留现有 FastAPI + Vite 主业务页面。打包 EXE 启动后先显示一个原生小窗口，窗口负责：

- 打开软件：启动或复用后端服务，并打开主界面。
- 扫描端口：显示当前目录和其他已运行服务。
- 关闭服务：调用当前服务的关闭接口或终止当前启动的服务进程。
- 显示根目录、数据目录、端口、PID、帮助文档、问题反馈。

浏览器中的 `#/launcher` 可暂时保留为降级页面，但 EXE 默认入口改为原生窗口。

### 2. 分镜内资产工具集成

把资产管理页中的核心工具抽成可复用组件，挂到分镜资产抽屉：

- 顶部工具栏：生图设置、批量生图、新建资产、批量删除、批量上传图片/音色、导入资产描述。
- 中间列表：保持已绑定资产高亮置顶；未绑定资产可选中绑定。
- 右侧/上方详情：选中资产后显示预览、名称、别名、提示词、模型、画幅、上传图片、上传音色和开始生图。
- 导出 JSON/CSV/图片包不进入分镜抽屉，避免误操作和空间拥挤。

目标是让用户在分镜工作台里完成“发现缺资产 -> 新建/上传/生图 -> 绑定到当前分镜”的闭环。

### 3. 多账号隔离

短期先保证不误导用户：

- 新增 CLI 隔离诊断：用临时空 profile 执行 `user_credit`，如果仍返回积分，则标记 `credential_isolation: unsupported_or_global`。
- 设置页显示醒目提示：当前官方 CLI 正在读取全局登录态，多账号不是真隔离。
- 当诊断失败时，多个账号不再累加相同积分；账号卡片提示“全局登录态，需重新隔离授权”。
- 单个账号登录按钮使用 headless/login/relogin 流程时，保存授权会话和返回结果，但必须校验 user_id 是否与其他账号重复。

中期再做凭据切换：

- 定位官方 CLI 的真实凭据来源。如果可复制文件，则每个账号维护自己的凭据快照，执行命令前切换到对应快照。
- 如果凭据来自 Windows Credential Manager 或浏览器全局授权，则在界面明确限制为单账号模式，或要求用户先退出全局账号再授权新账号。

## 风险

- 官方 CLI 未公开 Windows 凭据位置，多账号真隔离可能受限。
- 原生启动管理器如果使用 Tkinter，视觉可控但不如 Web 细腻；如果使用 PyWebView，视觉好但依赖更重。
- 分镜资产抽屉集成资产管理能力时，必须抽组件，不能复制整页大文件，否则维护成本会继续上升。

## 验收标准

- EXE 打开后先出现原生启动管理器窗口，不再默认打开网页版启动管理页。
- 用户可以从原生启动器打开主界面、查看根目录、查看端口、打开帮助和反馈链接、关闭当前服务。
- 分镜工作台添加资产时，可以直接新建资产、上传图片/音色、导入描述、批量删除、批量生图并绑定。
- 多账号页能明确显示 CLI 隔离诊断结果；当官方 CLI 返回同一个全局账号时，不再把积分重复累加成多个账号总额。
- 测试覆盖后端诊断、前端状态展示结构、打包入口和核心资产工具复用。
