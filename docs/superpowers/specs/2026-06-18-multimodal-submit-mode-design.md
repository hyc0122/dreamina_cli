# 全能参考提交模式设计

## 目标

在单个分镜提交和批量提交中明确选择视频生成模式，并让队列记录实际提交模式、绑定素材顺序和素材名称，避免“界面看似绑定资产，实际提交方式不可见”的问题。

## 模式

- `auto`（默认）：存在有效图片或视频参考时使用 `multimodal2video`，否则使用 `text2video`。
- `multimodal2video`：强制使用全能参考。提交前必须至少存在一张有效图片或一段有效视频，否则阻止入队并给出中文错误。
- `text2video`：仅发送提示词，不发送绑定图片、视频和音频。

单个提交和批量提交共用同一套生成参数控件，因此两处行为、默认值和校验完全一致。

## 素材映射

队列创建时冻结分镜绑定资产，顺序固定为角色、场景、道具，再接附加图片、视频和音频。全能参考提示词前自动加入可读映射，例如：

```text
【参考素材对应关系】
图片1：角色“沈云禾（年轻时期）”
图片2：场景“山路悬崖”
图片3：道具“白布担架”
音频1：角色“沈云禾（年轻时期）”的音色
```

官方 CLI 没有规定 `@图片1` 语法，因此不生成未经文档确认的 `@` 标记。文件通过重复的 `--image`、`--video`、`--audio` 参数提交，提示词中的“图片1”等按相同顺序进行自然语言说明。

## 校验与限制

- 图片最多 9 张，视频最多 3 段，音频最多 3 段。
- 全能参考至少需要一张图片或一段视频。
- 音频时长必须为 2-15 秒，生成视频时长必须为 4-15 秒。
- 纯文本模式不携带绑定素材，但绑定关系仍保留在项目中。
- 队列页展示实际生成模式和参考素材摘要，便于排查。

## 数据流

1. 前端参数控件保存 `generation_mode`。
2. 创建队列项时，后端冻结绑定资产并保存到 `asset_snapshot`。
3. worker 根据模式和有效文件选择 `text2video` 或 `multimodal2video`。
4. 全能参考模式生成素材映射前缀，并以相同顺序传递文件参数。
5. 队列保留最终提示词、模式、素材清单和 CLI 输出。

## 验证

- 单个和批量提交都保存模式。
- `auto` 有素材走全能参考、无素材走纯文本。
- 强制全能参考缺少素材时失败且不调用 CLI。
- 纯文本模式即使有绑定资产也不传文件。
- 素材映射编号和传给 CLI 的路径顺序一致。
