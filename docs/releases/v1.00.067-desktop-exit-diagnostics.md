# v1.00.067 启动器退出诊断与防误关闭

更新时间：2026-07-04 17:52:16 +08:00

## 更新名称

启动器退出诊断与防误关闭

## 背景

部分 Win10 电脑上打包后的程序会自动退出，但旧版本只记录了重复启动时间，没有记录退出前的触发来源、线程异常、worker 异常输出或关闭接口来源，无法判断是用户误关、接口触发、线程崩溃、worker 崩溃，还是系统或外部进程强制结束。

本次先不改业务架构，只增强诊断链路和防误退出能力。

## 修改内容

- 启动器安装退出诊断：
  - 记录启动器进程 PID、启动参数、是否为打包环境。
  - 启用 `faulthandler`，把底层崩溃堆栈写入独立日志。
  - 接管主线程 `sys.excepthook`，记录未捕获异常。
  - 接管 `threading.excepthook`，记录子线程未捕获异常。
  - 注册 `atexit`，记录正常解释器退出。
  - 捕获 `SIGTERM` / `SIGINT`，记录收到的系统信号。
  - 每 30 秒写入一次启动器心跳，确认进程退出前是否仍在运行。
- 启动器防误关闭：
  - 原生启动管理器右上角关闭按钮改为最小化。
  - 真正退出必须点击“关闭服务”按钮。
  - 点击“关闭服务”会写入明确日志。
- 关闭接口增强：
  - `/runtime/shutdown` 记录请求来源 IP、Origin、Referer。
  - 执行 `os._exit(0)` 前刷新所有日志 handler，减少退出前日志丢失。
- worker 输出保留：
  - 独立队列 worker 不再丢弃 stdout/stderr。
  - worker 标准输出和错误输出写入 `data/logs`，方便定位 worker 自身崩溃。

## 新增或增强的日志文件

以下路径中的 `data` 是打包程序运行目录下的数据目录，启动器界面会显示具体数据目录。

- `data/logs/desktop.log`
  - 启动器主日志。
  - 记录启动、心跳、窗口关闭、关闭服务按钮、关闭接口请求来源、正常退出等信息。
- `data/logs/desktop-faults.log`
  - Python faulthandler 日志。
  - 如果出现底层崩溃或 Python 无法正常抛出的错误，会优先查看这个文件。
- `data/logs/queue-worker.stdout.log`
  - 独立队列 worker 标准输出。
- `data/logs/queue-worker.stderr.log`
  - 独立队列 worker 错误输出。
  - 如果 worker 异常退出、任务线程崩溃或子进程报错，优先查看这个文件。

## 下次排查方法

对方电脑再次出现“程序自动没了”时，让对方压缩并发送：

```text
data/logs/desktop.log
data/logs/desktop-faults.log
data/logs/queue-worker.stdout.log
data/logs/queue-worker.stderr.log
```

判断规则：

- 如果 `desktop.log` 出现 `Native launcher close button pressed; minimizing instead of exiting`
  - 说明用户点过右上角关闭，但本版本会最小化，不会直接退出。
- 如果 `desktop.log` 出现 `Shutdown requested from native launcher button`
  - 说明有人点击了启动器里的“关闭服务”。
- 如果 `desktop.log` 出现 `Runtime shutdown requested by ...`
  - 说明前端或其他本机请求调用了 `/runtime/shutdown`。
  - 需要根据同一行的 IP、Origin、Referer 判断来源。
- 如果 `desktop.log` 出现 `Uncaught main thread exception`
  - 说明主线程 Python 异常导致退出。
- 如果 `desktop.log` 出现 `Uncaught thread exception`
  - 说明某个子线程异常，需要看 thread 名称和堆栈。
- 如果 `desktop-faults.log` 有堆栈
  - 优先按底层崩溃处理，可能是依赖库、Tk、系统环境或打包运行时问题。
- 如果 `queue-worker.stderr.log` 有异常
  - 优先检查 worker 或任务执行逻辑。
- 如果日志中没有正常退出、没有关闭接口、没有异常，且心跳突然中断
  - 更像系统、远程桌面会话、任务管理器、脚本或外部进程强制结束。

## 开发文件

- `packaging/dreamina_desktop.py`
  - 启动器诊断、窗口关闭拦截、心跳日志、异常钩子。
- `backend/app/main.py`
  - `/runtime/shutdown` 来源记录和退出前日志刷新。
- `backend/app/queue_worker_launcher.py`
  - 独立 worker stdout/stderr 日志落盘。
- `tests/test_desktop_packaging.py`
  - 启动器诊断和窗口关闭行为的源码级回归测试。
- `tests/test_runtime_manager.py`
  - 关闭接口原因记录回归测试。
- `tests/test_queue_worker_launcher.py`
  - worker 日志落盘回归测试。
