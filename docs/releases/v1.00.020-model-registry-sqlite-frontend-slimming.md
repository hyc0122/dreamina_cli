# v1.00.020 模型注册、记录存储和资产生图设置重构

- 更新时间：2026-06-21 03:07:55 +08:00
- 更新名称：模型注册、记录存储和资产生图设置重构

## 更新内容

- 即梦图片模型改为从 CLI 能力探测中增量登记：每次发现新图片模型会追加到后端已知列表，不会删除原有模型。
- 前端资产图片模型不再维护独立 `IMAGE_MODELS` 常量，统一读取后端 `/jimeng/settings/cli_capabilities` 返回的能力列表。
- 即梦 CLI 图片模型校验允许未来 `dreaminaX.Y` / `X.Y` 版本格式，避免新模型已显示但提交时被硬编码列表拒绝。
- 大模型资产生图记录迁移到 SQLite 的 `llm_asset_image_records` 表，保留完整 `record_json` 并建立项目、状态、提交时间相关索引。
- 旧版 `llm/asset_image_records.json` 会在首次访问时幂等导入一次，不删除旧文件，方便回滚和排查。
- 大模型设置页面移除“资产图片生图默认项”入口，资产生图视觉参数统一在资产管理的“生图设置”里配置。
- 资产生图设置新增“风格参考图”小页面，支持上传参考图并自动获取图片链接。
- 风格参考图上传后文件名按日期时间和随机后缀生成，例如 `asset-reference-20260621-030755-a1b2c3d4.png`，不会使用中文原文件名。
- 单个资产 AI 生图和批量资产生图统一读取全局风格参考图链接；没有上传参考图时，请求不携带 `reference_images` / `images` 参数。
- 单个资产右侧详情删除临时“参考图地址”输入，批量生图弹窗也不再提供单独参考图地址输入，避免多入口冲突。
- 资产管理右侧详情布局压缩：资产名/别名横向排列，角色分类与全局生图模型同排，音色文件和音色播放预览同排。
- 资产详情页拆出主图预览上传组件和历史生成图对比组件。
- 生成记录页拆出大模型生图记录列表组件，并复用统一的记录状态常量。
- README 当前版本更新为 `v1.00.020`，Python/npm 包版本同步为工具链可接受的 `1.0.20`。

## 修复问题

- 修复新增即梦图片模型需要在前端、后端能力列表、CLI 校验三处手工同步的问题。
- 修复大模型生图记录长期依赖 JSON 文件导致记录查询、删除、迁移和后续扩展不稳定的问题。
- 修复大模型设置里的“资产图片生图默认项”和资产管理“生图设置”容易让人误以为有两套生图参数的问题。
- 修复单个生图和批量生图各自填写参考图地址导致参数不一致的问题。
- 修复中文参考图文件名上传后在路径和日志里可能乱码、难以识别的问题。

## 使用说明

1. 在资产管理点击“生图设置”，进入“风格参考图”小页面上传参考图片。
2. 上传成功后页面会显示自动获取到的图片链接；单个资产 AI 生图和批量生图会自动使用这些链接。
3. 如果“风格参考图”为空，生图请求不会上传参考图参数。
4. 新增即梦图片模型时，先确保本机即梦 CLI 能在帮助或能力输出中显示该模型；打开应用能力接口后，后端会在原有模型基础上追加新模型。
5. 大模型生图历史记录会自动迁移到 SQLite，旧 JSON 文件保留在本地，不需要手动处理。
