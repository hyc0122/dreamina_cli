# v1.00.039 网页 SessionID 测试链路重构

更新时间：2026-06-22 20:39:21 +08:00

## 更新名称

网页 SessionID 测试链路重构

## 更新内容

- 按 `jimeng-web2api-master` 的 `signed_post` 原理重写网页测试后端：统一拼接即梦网页公共参数、生成签名、发送 `POST /mweb/v1/aigc_draft/generate`。
- SessionID Cookie 改为只拼 `sessionid=...`，不再额外伪造 `sessionid_ss`、`sid_tt`、`sid_guard` 等字段。
- 提交成功后优先提取即梦返回的真实 `history_id`，并把任务绑定到提交时选择的账号，后续轮询始终使用同一个账号的 sessionid。
- 轮询改为调用 `POST /mweb/v1/get_history_by_ids`，按网页历史接口解析状态、失败原因、候选视频和最终视频地址。
- 即梦返回 `ret != 0`，例如 `4013` 风控失败时，测试任务会立即标记为失败并展示原始错误，不再误判成“轮询中”。
- 网页测试页面保留自动轮询和诊断展示，方便看到 submit/history、最近轮询时间、模型参数和错误详情。
- 修正 `pyproject.toml` 中误把项目版本写入 `ruff.target-version` 的配置问题，恢复为 Python 目标版本 `py311`。

重点参考位置：

## 问题原因

旧实现虽然也能把 SessionID 拼成 Cookie，但请求结构和参考项目不完全一致，并且在即梦返回失败 ret 时仍可能拿本地生成的 `submit_id` 兜底进入轮询，导致页面看起来像“后台没反应”。

这次改为按参考项目的签名请求链路执行：提交接口返回成功才进入轮询，失败 ret 直接失败；提交成功后使用真实 `history_id` 查历史结果，避免反复用错误 ID 查询。
