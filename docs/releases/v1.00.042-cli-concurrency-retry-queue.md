# v1.00.042 即梦 CLI 并发上限回队列修复

更新时间：2026-06-23 00:49:02 +08:00

## 更新名称

即梦 CLI 并发或队列上限任务回到等待重试

## 修改内容

- 修复即梦 CLI 返回 `ExceededConcurrencyLimit`、`并发`、`达到上限` 等文案时，队列页误显示为“失败”的问题。
- 后端错误分类器将“并发/队列达到上限”归类为 `QUEUE_FULL`，交给队列策略按 `retry_wait` 处理。
- 队列页状态判断优先尊重 `waiting`、`retry_wait`、`blocked` 这些本地队列状态，不再被上一轮 `gen_status=failed` 或错误文案覆盖成失败。
- 等待重试项的状态说明改为显示队列位置，避免 tooltip/detail 继续显示 `failed` 误导判断。
- 增加后端和前端回归测试，覆盖并发上限文案、scheduler 重试、`retry_wait` 前端归类。

## 影响范围

- 即梦排队页的状态统计、状态筛选和状态徽章。
- 独立 worker 提交即梦 CLI 任务时遇到官方并发/队列上限的重试处理。
- 不影响真正的参数错误、登录错误、余额不足等不可继续提交的问题。

## 验证重点

- 当即梦返回并发或队列达到上限时，任务应显示在“等待”列表，而不是“失败”列表。
- 任务应保留在本地队列，等待 `next_attempt_at` 到期后由 worker 继续提交。
- 队列页失败数量不应因为 `retry_wait + gen_status=failed` 被错误增加。
