# v1.00.072 分镜全文角色与场景匹配修复

更新时间：2026-07-27 12:38:50 +08:00

## 问题表现

- 分镜提示词正文已经出现角色名，但角色资产没有自动绑定。
- 场景名称不在 `场景：` 字段开头，或出现在镜号描述、动作说明等正文位置时，可能无法匹配。
- 同一段文字同时存在同名角色资产和场景资产时，原来的全局占位规则可能只保留其中一种类型。

## 根因

自动绑定原来主要依赖 `人物：`、`场景：`、`道具：` 等结构化字段。分镜正文虽然可以显示高亮，但不一定进入自动绑定候选；不同资产类型还共用同一组文本占位，角色与场景可能互相排斥。

这不是分镜文字太长造成的。核心原因是自动绑定的检索范围和跨类型占位规则不符合实际使用方式。

## 修改内容

1. 角色资产改为扫描完整分镜提示词，只要正文出现角色完整名称或别名，就进入角色库匹配。
2. 场景资产同样扫描完整分镜提示词，只要正文出现场景完整名称或别名，就进入场景库匹配。
3. 角色库和场景库独立查找、独立计算文本占位；同一文字在两类资产中都存在时，可以分别建立绑定。
4. 场景候选继续按完整名称长度排序，同一分镜只绑定一个最具体、最准确的场景。
5. 角色资格后缀继续严格匹配，例如 `沈云禾[年轻时期]` 可以匹配 `沈云禾(年轻时期)`，不会退化成只按 `沈云禾` 绑定。
6. 同一物理行连续出现 `场景：...。人物：...` 时，会分别截取字段，不再把后续人物内容吞进场景字段。
7. 道具仍只读取 `道具：` 结构化列表，避免普通叙述中的常用物品被大量误绑定。

## 匹配规则

- 分镜全文出现角色完整名称或别名：从角色库查找并绑定角色。
- 分镜全文出现场景完整名称或别名：从场景库查找并绑定场景。
- 同一分镜出现多个场景名称：只绑定完整名称最长、优先级最高的一个场景。
- 角色和场景分别匹配，不会因为文字位置重叠而互相覆盖。
- 资产名称没有在分镜中出现：不自动绑定。
